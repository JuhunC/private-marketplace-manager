OPERATOR GUIDE

Your extension library, kept in sync.

The manager writes validated, original VSIX packages into the directory already scanned by Microsoft Private Marketplace. The cross-platform sync client downloads packages from the public marketplace and uploads them over this authenticated API.

Deploy the manager

Mount the existing extension directory at /data/extensions and a separate persistent state volume at /data/state. The container runs as UID/GID 10001; grant that identity write access. Configure PUBLIC_URL to the exact browser origin and use an internal HTTPS reverse proxy.

Provide API_TOKEN_FILE (at least 32 characters) and ADMIN_PASSWORD_FILE (at least 12 characters). Sign into the webpage using the operator password; use the separate API token for automation. Never include tokens in URLs or command-line arguments.

Run the cross-platform client

Download the release for Windows, Linux, or macOS and your CPU. Create extensions.txt with one extension identifier per line. The list is reread on every run. Adding an ID backfills all available history; removing one preserves uploaded files.

ms-vscode.hexeditor
# Add your own publisher.extension identifiers

Save connection settings in sync-settings.json:

{
  "serverUrl": "https://marketplace-manager.example.internal",
  "tokenFile": "api-token.txt",
  "workDir": "work",
  "concurrency": 2
}

Restrict the token file to the execution account (Unix: chmod 600 api-token.txt; Windows: file ACLs). Relative settings paths are resolved from the configuration file.

marketplace-sync discover --list extensions.txt --config sync-settings.json
marketplace-sync sync --list extensions.txt --config sync-settings.json

Use marketplace-sync.exe on Windows. Schedule the same command using Task Scheduler, a systemd timer/cron, or launchd. No Go, Python, or PowerShell runtime is needed for the executable.

What “all versions” includes

The collector requests all exposed versions and assets, including prereleases and every published platform variant. The host OS does not restrict packages. Removed or undiscoverable source versions cannot be recovered automatically. The client reports incomplete discovery or failed packages and returns a nonzero exit status.

Every run compares server inventory before downloading. Replacing the client machine only requires copying the list/settings and provisioning a new credential. Already-stored files are skipped. Preserve your active identifier list separately: archived packages cannot reconstruct which IDs you still want to collect.

REST API

Download OpenAPI specification. Authenticate with Authorization: Bearer TOKEN. Upload original VSIX bytes as application/octet-stream to POST /api/v1/extensions. A 201 response confirms durable storage; 200 confirms identical content was already present. Conflicting bytes for the same identity return 409.

Optional expected identity fields are query parameters id, version, and platform. Supply X-Content-SHA256 and Idempotency-Key for verification and retry receipts. Maximum upload size defaults to 2 GiB. Packages are validated before publication; uploads do not execute extension code.

Operations

Keep all previous versions: there is no automatic deletion or pruning. Startup inventories pre-existing files as externally managed and reconciles published files with state. Avoid external writers while the manager is running; restart after manual directory changes. Back up the extension folder and state volume consistently while the manager is stopped.

File storage and visibility in VS Code are different outcomes. Verify the exact version/platform in your existing marketplace. Multiple-version behavior, refresh timing, and signature handling must be tested against your deployed marketplace release.

Troubleshooting

  • Login origin error: set PUBLIC_URL to the exact HTTPS origin used in the browser.
  • 401: check token provisioning or sign in again. 403: verify origin and CSRF behavior.
  • 409: identity/content conflict or destination publication failure; investigate without overwriting the original file.
  • 413: increase MAX_UPLOAD_BYTES and reverse-proxy limits if the package is approved and disk permits.
  • 422: package structure, checksum, or expected identity failed validation.
  • 429: retry after the supplied delay. 507: check disk space, permissions, and staging writes.
  • Proxy/CA problems: set HTTPS_PROXY/NO_PROXY and the client's caFile. Keep certificate validation enabled.

The initial release uses one operator password and one scoped-purpose automation token. Restart with changed secret files to rotate credentials; active browser sessions end on restart. Separate accounts, per-token roles, automatic marketplace visibility probes, malware scanning, and publisher-signature verification are not included in this release. SHA-256 verifies transfer identity, not publisher trust.
